## Linux (POSIX) path checks

Read, not executed:

- `proposalApply` selects `realpathSync.native` only when `process.platform === 'win32'`. On every
  other platform it calls `realpathSync` at the same three sites as r9, so the exact-equality checks
  are byte-for-byte the r9 logic.
- `locate()`, `resolvePath()` and `toRepoRelative()` are unchanged. On Linux, `realpathSync.native`
  inside `realish()` is libc `realpath`, which does not fold case.
- A project spelling that differs in case on Linux names a different path. It fails to resolve, or it
  resolves elsewhere, and the exception is refused.
- On non-win32, `f22Spellings` has one native spelling. The allow group and the four negative
  scenarios run once each (5 tests). The POSIX-only test (`:1394-1409`) expects 2 for three
  cases: a case-distinct `docs/PROPOSALS/control.patch`, a file symlink
  `docs/proposals/escape.patch` → `docs/outside.patch`, and `docs/proposals` replaced by a symlink to
  `docs/PROPOSALS`. With the 69 originals and the F23 test, Linux should define 76 tests.

What this Windows machine cannot prove:

- the POSIX-only test and the native-spelling matrix actually passing under Linux;
- the CI test count;
- POSIX symlink behavior.

`process.platform` cannot be faked here without mixing Windows `path` semantics into the
run, so no simulation was attempted. CI (`ubuntu-latest`) on the pushed head is the first Linux
evidence. macOS was not considered because CI does not use it.
