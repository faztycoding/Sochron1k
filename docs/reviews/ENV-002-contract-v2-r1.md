### F3 · High · `libproc` and `libc` do not load, and a short library name is searched in the working directory first
- **Where:** contract :177 "เปิดเฉพาะ `libproc` และ `libc` ด้วยชื่อตรงตัว … อ่าน error ด้วย `ctypes.get_errno()`", repeated in :223.
- **Evidence:** Probe (all four lenses, repeated by the consolidator): `ctypes.CDLL('libproc')` and `ctypes.CDLL('libc')` raise OSError ("dlopen(libproc, 0x0006): tried: 'libproc' (no such file)"); `libproc.dylib`, `libc.dylib`, `/usr/lib/libproc.dylib`, `/usr/lib/libc.dylib` and `/usr/lib/libSystem.B.dylib` load, and each handle has `proc_listallpids`, `proc_pidpath` and `getfsstat`. `os.path.exists('/usr/lib/libproc.dylib')` is False (dyld shared cache). `man dlopen`, SEARCHING: "When path does not contain a slash character … If $DYLD_LIBRARY_PATH was set at launch, dyld will first look in that directory … Next, if the process is unrestricted, dyld will search in the current working directory … and then in /usr/lib/" (with `/usr/local/lib/` between the last two). `codesign -dv` of the uv interpreter: `flags=0x20002(adhoc,linker-signed)` (no hardened runtime).
