## Findings, corrections and process

Initial tests failed rather than being relabeled PASS: fractional receipt parsing
raises 22P02 before bigint insertion (now asserted explicitly); the precision
negative fixture originally ended in zero and was still valid at nine decimals
(now requires eight). Timestamp validation was tightened to reject PostgreSQL's
hour-24/second normalization. Fresh migration checks then proved the corrected path.

Grant inspection found that Supabase defaults left service-role TRUNCATE/TRIGGER
and other maintenance grants despite a narrow additive GRANT. A regression test
failed on the actual existing `bars` grants. The migration now explicitly revokes
backend table privileges before granting only bar CRUD and archive SELECT/INSERT.
This keeps intended generic operations but blocks row-trigger bypass. Other tables
and browser grants are unchanged. A DBA can still change the schema; this is not
a defense against a compromised administrator.

The migration was generated using CLI `db pull native_m1_receiver --local --yes
--schema public,sochron_private`, then reviewed and tightened with explicit
default-privilege revokes. Existing migration files were not rewritten. pgTAP,
fresh replay, forward compatibility and races ran on this exact resulting SQL.

Skills used: `supabase` for imperative generation, role review, advisors and
versioned local verification; `supabase-postgres-best-practices` for exact numeric
types, owner RLS, uniqueness and transactional conflict handling;
`sochron-risk-recovery` for immutable identifiers and independent concurrent-effect
oracles. `pdf` guided read-only inspection of blueprint sections 13-16 and 22-23.
These instructions shaped the implementation, not proof of broker enforcement.
