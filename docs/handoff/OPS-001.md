test step:

```bash
set -o pipefail
uv run --locked pytest tests -q -p no:cacheprovider | tee pytest-output.txt
summary="$(tail -n 1 pytest-output.txt)"
if [[ ! "$summary" =~ ^[0-9]+\ passed ]]; then
  echo "::error::no pytest summary line of the form '<n> passed ...' (last line: $summary)"
  exit 1
fi
if [[ "$summary" == *skipped* ]]; then
  echo "::error::skipped tests do not count as passed (AGENTS.md): $summary"
  exit 1
fi
```

How it fails: GitHub runs `run:` steps without `shell:` as `bash -e {0}`; with `set -o pipefail` a failing
pytest ends the step with pytest's own exit code (1 for failures, 2 for interruption/usage, 5 for no tests),
and a failing `uv run --locked` ends it with uv's exit code (2 on a lock mismatch). On a clean run the last
line of `-q` output is `N passed in Xs`; a skip makes it `N passed, M skipped in Xs` (or `M skipped in Xs`
with no pass), and either form exits 1 through the checks above. If a future shell ran without `-e`, the
checks still exit 1 because a failed run's last line never starts with `<n> passed`. `xfail`/`xpass` are not
treated as failures by this step (the red-flag scan flags the marker); the contract names skip only.
`-rs` from the contract's step list was not added so the pytest arguments stay identical to the local verified
command; the `::error::` line prints the summary that names the skip count.
