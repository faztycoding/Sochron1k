### Correction of the round-1 sentence (F2)

Round 1 (section "The patch", above) said: "If a future shell ran without `-e`, the checks still exit 1 because a
failed run's last line never starts with `<n> passed`." **That is wrong.**
- pytest orders the parts `failed, passed, skipped, deselected, xfailed, xpassed, warnings, error, …`
  (`terminal.py:63-75`). Only `failed` sorts before `passed`.
- So an error-only run ends with `<n> passed, <m> error(s) in …`. That starts with `<n> passed` and contains no
  `skipped`, so the round-1 step without `-e` exits 0. The same holds for xfailed, xpassed, deselected and subtests,
  with or without `-e`, whenever pytest itself exits 0.
- The round-1 note "`xfail`/`xpass` are not treated as failures by this step" is superseded: round 2 makes them red.

What holds after round 2:
- **Holds with or without `-e`:** every non-pass outcome that pytest prints on the summary line makes the step exit 1
  through the allow-list. So does a uv failure, which leaves `pytest-output.txt` empty and the last line empty.
- **Covered only by `-e`, now explicit through `shell: bash`:** a non-zero pytest exit whose last line is still an

### What the step does

The patch inserts this step between "Sync the environment from uv.lock …" and "Python tests …" (post-apply lines
73–78; line 78 is the blank separator):

```yaml
      # Red unless zoneinfo.TZPATH is (), so zoneinfo reads only tzdata (D-013 amendment 2026-10-23).
      - name: Check zoneinfo time zone source (red unless zoneinfo.TZPATH is empty)
        shell: bash
        run: |
          uv run --locked --no-build python -c "import importlib.metadata, sys, zoneinfo; print('zoneinfo.TZPATH =', zoneinfo.TZPATH); print('tzdata version =', importlib.metadata.version('tzdata')); sys.exit(0 if zoneinfo.TZPATH == () else 1)"
```

- **Same interpreter, flags and environment as the tests.**
  - It uses `uv run --locked --no-build`, like the test step. So it selects `UV_PYTHON=3.12.15` (from setup-uv) and
    runs in the project `.venv` that the previous step synced from `uv.lock`.
  - The job-level `PYTHONTZPATH: ""` applies to this step as to every other. The step adds no `env:` of its own.
- **What it prints, in this order:**
  - `zoneinfo.TZPATH = <tuple>`
  - `tzdata version = <version>`: the version of the installed `tzdata` distribution, from
    `importlib.metadata.version`.
- **Fail-closed paths:**
  - **`TZPATH` is not `()`.** Python exits 1. This is the case the step exists for: the runner dropped the empty
    value, so `zoneinfo` fell back to the build's compiled-in search path.
  - **`tzdata` is not installed.** `importlib.metadata.version` raises `PackageNotFoundError`, and Python exits 1
    with a traceback, after the `TZPATH` line has printed.
  - **uv fails.** A lock mismatch or a missing interpreter makes uv exit non-zero.
  - **How the exit code reaches the job.** `shell: bash` runs the block with `-eo pipefail`, so the step ends with
    `uv run`'s exit code. `uv run` passes the child's exit code through: N3 in `docs/evidence/OPS-001.md:43` shows
    pytest's exit 1 coming through `uv run` under the same shell form. A failed step skips the tests (default
    `if: success()`), and the job is red.
- **What it does not check.** It prints the `tzdata` version but does not compare it to `2026.5`, as the task
  specified. The version is already pinned by `uv.lock` under `--locked` (hash-checked by uv). The step adds no
  `::error::` annotation. The red step's log shows the offending tuple on its first line.
- **Why `TZPATH == ()` means "only the `tzdata` package":**
  - `zoneinfo.TZPATH` is a module `__getattr__` that returns `_tzpath.TZPATH`
    (`Lib/zoneinfo/__init__.py:23-25`, uv-managed CPython 3.12.15 on the dev machine).
  - That is the same global that `find_tzfile` loops over (`_tzpath.py:74`), so the step reads the live value used by
    the lookup, not a copy.
  - With `()`, `find_tzfile` returns `None` and `ZoneInfo` loads from the `tzdata` package (round-3 source reading
    above: `_zoneinfo.py:65-70`, `_common.py:4-24`).
  - The round-3 caveat about the C accelerator `Modules/_zoneinfo.c` (not re-read) still applies. It does not affect
    this check, because the check reads the shared `_tzpath.TZPATH`.
