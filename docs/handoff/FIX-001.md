## How the checker changes

`_SIDE_EFFECTS` holds the contract list ("Inputs / outputs / errors"), item by item:
- clock: `time.localtime`, `gmtime`, `ctime`, `asctime`, `strftime`, `mktime`, `clock_gettime`, `clock_gettime_ns`,
  `thread_time`, `thread_time_ns`
- randomness: `os.urandom`, `os.getrandom`, `secrets`, `uuid`, `random.SystemRandom`
- process: `subprocess`, `multiprocessing`, `os.system`, `os.popen`, `os.fork`, `os.kill`; plus `os.exec*` and
  `os.spawn*` as name families (`_OS_PROCESS_FAMILIES`)
- console stream: `sys.stdout`, `sys.stderr`, `sys.stdin`, `sys.__stdout__`, `sys.__stderr__`
- network: `http`, `ssl`. `socket` already has its CORE-001 rules, which stay unchanged.

A name covers its attributes (`_within`), so `sys.stdout.write`, `uuid.uuid4` and `http.client` match. Names are
resolved through the existing `_qualified` and bindings. That covers `import x as y` aliases,
`from x import y [as z]`, assignment aliases (`lt = time.localtime`) and imports inside function bodies. The
checker reports:
- `line N: forbidden <category> access <name>` for any reference: a call, an attribute or name read, a
  default argument, a callback. `check_reference` already runs for every `Name` and `Attribute`.
- `line N: forbidden <category> import <name>` for `import x` and `from x import y` bindings.

A bare name in Store/Del context is a binding, not a use, so it is not reported. Examples: a dataclass field
`uuid: str`, or `uuid = "…"`. Attribute stores such as `sys.stdout = w` are still reported.

`_inspect_source` is shared by all three inspection functions, so the change covers `sochron.timebase`,
`sochron.core`, `sochron.costs` and `sochron.risk` at once. `_inspect_costs_source` and `_inspect_risk_source`
are unchanged.

## Limitations (measured with `harness\limits.py`; none of these is claimed as caught)

Not detected (no finding):
- **Dynamic access** (the contract's negative case): `getattr(time, "localtime")()`, `vars(os)["urandom"]`,
  `sys.modules["time"].localtime()` and `exec("import subprocess")`. `importlib.__import__` is also missed,
  because the existing `dynamic_imports` set lists only `__import__`, `builtins.__import__` and
  `importlib.import_module`.
- **A module reached through another module's attribute**, such as `os.sys.stdout.write(...)`.
- **Underlying or private stdlib modules**, such as `nt.system`/`posix.system` and `import _socket`.
  `_allowed_import` admits every stdlib name except `socket` itself.
- **Siblings that the contract list does not name:**
  - process: `os.posix_spawn`/`posix_spawnp` (outside the `os.spawn*` glob), `os.forkpty`, `os.killpg`,
    `os.startfile`, `asyncio.create_subprocess_*`, `concurrent.futures.ProcessPoolExecutor`
  - console: `sys.__stdin__`
  - stderr writers: `logging` and `warnings`
  - randomness in timebase/core: `random.random()`. Costs and risk ban `random` imports, but timebase and core
    still allow `import random`; FIX-001 adds only `random.SystemRandom`.
- **Function signature annotations**, which `visit_FunctionDef` does not visit (existing behaviour).
- **CORE-001 call-only clocks used as values**, such as `field(default_factory=time.time)`. The new FIX-001
  names are reference-based. The old `clocks`/`direct_io` sets were left call-only, so their meaning is
  unchanged.

Over-reported:
- **Loop, comprehension or with-target names equal to a module name.** These names are not tracked as bindings,
  so the checker treats them as the module. Measured: `for time in times: time.strftime("%H")`,
  `[time.strftime("%H") for time in times]` and `with … as uuid: uuid.hex` are all reported. Teaching the checker
  these bindings would change the binding logic that the CORE-001 checks also use. In adversarial cases, such as
  `for time in [time]: time.time()`, that would weaken them, so it was left alone (AC-04). Workaround: rename
  the variable.
- **New clock names with an argument**, such as `time.gmtime(0)`, are reported by design. The contract names
  these calls "that read the current time". A static check cannot tell `time.gmtime(None)` or `time.gmtime(x)`
  from a constant. `localtime`, `mktime`, `ctime` and `strftime` with a value still read the host time zone or
  locale. So every reference is reported (the comment above `_SIDE_EFFECTS` says this).

### How the checker resolves names now (Python scoping)

Each rule was checked at run time with CPython 3.12.15 (`harness\scope_proof.py`, evidence 8).
- **Class bodies.**
  - A class body sees its own names.
  - Methods, lambdas, nested class bodies and comprehension bodies defined in it do not. They start from the
    nearest enclosing function or module scope (`self.enclosing`).
  - Only a comprehension's first iterable runs in the class body.
  - A method's own name is a class attribute, so `def time(self): return time.localtime()` reads the module.
- **Parameters and function locals.**
  - Function and lambda parameters, and names assigned in a function body, are local to that function. Functions
    already worked this way; lambdas now do too.
  - Module-level rebinding is unchanged: `time = 0` at module level still shadows the module for the rest of the
    module.
- **Unpacking.**
  - `a, b = x` binds both names.
  - A same-length tuple or list on the right pairs by position, and all values resolve before any binding. So
    `clock, other = time, 0` keeps `clock` as the module, and a swap moves it.
  - Any other right-hand side binds the names to no module.
- **Walrus.** `(name := value)` binds like an assignment.
- **Handlers and captures.**
  - `except E as name` binds the exception inside the handler.
  - A `match` capture binds inside its case. A top-level capture binds the subject, so
    `match time: case m: m.gmtime()` is still reported. A nested capture binds a part of it.
  - Afterwards, a name still bound to no module gets its old binding back. Python deletes an except-as name, and a
    capture binds only when its case matches.
  - If the body rebinds the name, for example `found = time`, that binding stays.
- **Annotations without a value.** `time: int`, such as a dataclass field, binds nothing, as in Python. HEAD bound
  the name to no module, which hid `time` in the rest of a class or module body.
- **Stores.** A bare name in Store/Del context is never a use.
  - Round 1 skipped it for the FIX-001 names only. It now also covers the CORE-001 rule.
  - So a field or variable named `socket` is not reported, and neither is a store to a name imported as
    `os.environ`.
  - The `socket` import, the `from os import environ` import and every read are still reported.

### How the checker works now

`_inspect_source` runs three passes over the same tree and returns the sorted union of their findings:
1. **`Inspector()`**: all rules (CORE-001 and FIX-001), with round-2 scoping plus the round-3 changes below. Names are
   bound as they are where each body is defined.
2. **`Inspector(late=True)`**: the same rules. Each function or lambda body is checked after its module or function body
   has ended, with the names bound there at the end, because a body runs when it is called.
3. **`OriginalInspector`**: HEAD's `Inspector`, verbatim. The class body is AST-identical, and its 97 lines are
   textually identical. It runs only the CORE-001 rules, with HEAD's name resolution.

**Why HEAD's findings are a subset.** Pass 3 is HEAD's code, and a union only adds. `_inspect_costs_source` and
`_inspect_risk_source` are unchanged and call `_inspect_source`. So every finding HEAD reports on any source is
reported again, by construction. The corpus check (evidence 5) confirms it.

**Why F2 stays fixed.** The FIX-001 rules run only in passes 1 and 2, so their round-2 scoping stays.

Round-3 changes in passes 1 and 2 (each Python fact checked at run time on 3.12.15, `evidence-semantics.log`):
- **Evaluation order (F6).** The visits now follow the order in which Python evaluates:
  - An assignment visits the value, then the targets in order.
  - An annotated assignment visits the value, then the target, then the annotation.
  - `for` visits the iterable, then the target, the body and the `else`.
  - A dict display visits each key, then its value, pair by pair.
  - Every comprehension, not only those in class bodies, visits the first iterable, then each target, condition and
    later iterable, and the element last (a key before its value).
  - A value resolves as it was when Python evaluated it (`self.resolved`). So in `clock, other = time, (time := 0)`,
    `clock` stays the module.
- **Match captures (F7, F8).** `captures()` decides what each capture holds:
  - An `as` name, and each or-pattern alternative, hold the whole subject.
  - A class-pattern keyword holds that attribute of it: `case object(localtime=clock)` binds `time.localtime`, and
    nested keywords chain.
  - Positional, sequence, mapping and star captures hold no module.
  - Of the alternatives, the first binding to a module is kept.
- **`global` and `nonlocal` (F8).** `declarations()` maps each name a function or class body declares global (the module
  scope) or nonlocal (the nearest enclosing function). The body reads the name from that scope. `bind()` also writes
  the binding there, but only a module: a function that may never run hides no module. This "may" rule keeps N03
  reported.
- **Late pass (F8, N23).** See pass 2 above.

### Limitations (round 3; none of these is claimed as caught)

This list supplements the round-1 and round-2 lists. They still hold, with two exceptions: F3-d (late aliased import)
and the module-level comprehension order are now caught. For the CORE-001 rules, `OriginalInspector` still reports
whatever HEAD reported in these forms, for example N24, N25, N27 and N28.

Not detected; the runtime recorder shows each call executes (`probes-r3.log`):
- **X04, `nonlocal` through a function that does not bind the name.** Only the nearest enclosing function is updated:
  `def a(): clock = None` / `def b(): def c(): nonlocal clock; clock = time` / `c()` / `b()` /
  `return clock.localtime()`.
- **X05, a global write in a function defined after its reader.** Both passes run bodies in source order:
  `time = None` / `def label(): return time.localtime()` / `def setup(): global time; import time`.
- **X06, a module bound only between a definition and a later rebinding.** The late pass sees only the final binding:
  `def f(): return t.localtime()` / `import time as t` / `X = f()` / `t = None`.
- **X07, a generator-expression body that runs after a later import.** Generator bodies are not held back:
  `G = (t.localtime() for _ in [0])` / `import time as t` / `X = list(G)`.
- **Class-pattern positional captures.** `case C(x)` depends on `__match_args__`; it holds no module. On a module
  subject Python rejects them anyway: `case object(x)` and `case types.ModuleType(x)` raise TypeError ("accepts 0
  positional sub-patterns"), checked at run time.
- **Unchanged from earlier rounds:**
  - the module passed as a value: a default argument (F3-a, N26), a lambda argument, a container, unpacking from a
    call, a walrus used as a value
  - `self.attr` (N08)
  - conditional rebinding (N29)
  - class keyword arguments (N31) and parameter annotations (N32)
  - dynamic access, `os.sys`, private modules, siblings the contract does not name
  - CORE-001 call-only clocks used as values
- **F5 host reads:** deferred by the owner.

Over-reported (conservative): see "Findings outside HEAD and round 2" above, plus the round-2 items. Those are
